# 词书内随机选词：详细设计审核稿

日期：2026-10-06。状态：用户已整体审核通过并授权开工；制作版已实施，自动检查通过，人工验收待进行。正式站点尚未更新。

## 1. 产品规则

保留默认顺序选词，增加词书内随机选词。设置页增加“新词选取”分段按钮，选项完整显示“顺序选词”和“随机选词”；今日学习页不放该开关。

模式作为一项通用学习偏好保存，不按词书另存一份，也不改变词表浏览的排序。数量沿用每日新词设置；额外学习仍按现有每批最多 10 词接续，不新增每日上限。

候选词均来自任务所属词书，先按规范化单词去重、排除该词书内已完成学习的词，再进行以下选择：

- 顺序模式：按词书默认顺序取前 N 词，保持现有行为。
- 随机模式：在全部剩余候选中无放回随机抽取最多 N 词，不只打乱原来的前 N 词；抽出的顺序也保存为任务顺序。
- 剩余数量不足时使用全部剩余词，不重复补足，不跨词书取词。

未完成过的尝试记录不等于已完成，仍可成为后续新词候选。复习选择、间隔排程、四轮回忆、释义选项、反馈和更正规则不改变；随机只决定新批次的词集及初始顺序，不在每轮回忆或刷新时重新抽词。

## 2. 设置、快照与生效时间

“新词选取”放在设置页上部固定高度的控制区；桌面紧凑呈现，手机两项均可触摸且文字不省略。现有设置卡片及 A 胶囊滚轮形态保留，不因切换模式展开额外说明或推动其他控件。

点击只修改设置草稿，和日期、词书、数量一起点击“保存设置”才生效。没有单独自动保存。沿用未保存修改提示、放弃确认、存储冲突和重新读取机制；保存失败保留草稿并显示原有错误反馈，不假装已保存。

新建今日任务时，把选词模式保存在该任务的设置快照中。之后的新额外批次沿用这个当日快照，而不是后来修改的全局设置。

| 场景 | 结果 |
| --- | --- |
| 今日任务尚未创建，保存随机模式后开始 | 当前词书内随机创建今日任务 |
| 今日任务已经创建，再保存另一模式 | 原词集、顺序、当前词及进度不变；新模式用于之后创建的今日任务 |
| 今日任务完成后额外学习 | 沿用今日任务的词书、模式与其他设置，每个新批次只抽取剩余未完成词 |
| 刷新、离开再进入 | 恢复已保存任务或当前额外批次，不重新抽取 |
| 今天无剩余新词 | 今日保存原有空任务行为；额外过程沿用原有已耗尽行为，不生成重复空批次 |
| 旧任务／旧偏好 | 按顺序模式解释，保留原记录 |

设置页继续使用已有短提示“新设置用于之后创建的任务；今天已经开始的任务不会被改写。”，无需在今日页加入说明段落。

## 3. 选词流程与失败处理

现有 `LearningSession.jsx` 先挑选 ID，再加载词条详情，确认可展示后才创建任务。随机选词沿用这个顺序：读取词书顺序 → 过滤候选 → 选择候选 ID → 加载所选详情 → 检查日期／设置／状态 → 持有写锁保存任务 → 展示。

顺序与随机共用一个小型纯函数，拟新增 `src/data/learning/selection.js`，统一去重、排除已完成、模式验证和数量裁切。随机采用洗牌后取 N 的办法，可注入随机来源用于确定性测试；不使用 `sort(() => Math.random() - 0.5)`，不需要保存完整词书随机序列或随机种子。

数据层不进行第二次独立洗牌，否则加载的词条可能与保存任务不一致。它继续验证候选，恢复已有任务时以保存结果为准。若候选在加载与写入之间被其他操作改变，不以静默裁切生成另一份批次，应报告冲突并重新读取，避免漏词或意外空批次。原有写锁、设置一致性、日期及会话序号保护保留。

词书读取、详情缺失或保存失败时不创建半成品任务；用户重试。未成功保存的尝试不承诺相同抽取结果，成功保存后必须稳定恢复。已经耗尽的额外过程继续按原行为恢复。

## 4. 数据兼容与已验收服务

现有浏览器数据版本为 6，设置字段严格验证。拟提升为 7，增加 `newWordSelectionMode: 'sequential' | 'random'`，默认 `sequential`。为合法旧记录的全局设置及每个历史任务设置快照补顺序模式；先按原版本完整验证，再迁移，保留全部词集、进度、事件、日期和历史。非法值必须拒绝，不能用默认值掩盖损坏记录。

迁移须支持所有当前可恢复的 v1–v6 输入，且额外批次的设置快照仍与所属今日任务一致。设置页字段列表、草稿比较与首次设置流程须兼容默认值，首次设置不强迫用户再回答一个问题。旧数据迁移沿用现有存储保存路径，不清空正式记录。

现有 `src/data/assistant/snapshotToken.js` 根据 `DEFAULT_SETTINGS` 自动发送字段，但本机服务严格接受现有七项设置。新增字段后必须把请求字段与浏览器偏好分开：请求继续明确选取已批准的七字段，不向现有服务发送新字段，不改契约版本或 Python 服务。

摘要依据仍对完整浏览器状态计算校验值，模式变化也会使旧摘要失效；不能通过省略新偏好而削弱状态绑定。未来 P-03-B 若需要模式信息，单独在其方案中审核，本文不提前增加服务或模型字段。

部署后可能保存 v7 记录，不能简单回退到不支持 v7 的旧前端。需要修复时交付兼容 v7 的修正版本，不要求用户清空学习记录。

## 5. 比较过的方案

采用“每次新建任务／批次抽一次并保存”：改动集中、恢复稳定，符合每日固定任务规则。

不采用“每进入页面抽一次”，因为会改写当日任务；不采用“为全书预存随机排列”，因为要额外维护词书版本、序列和游标，当前需求无需这些状态。

## 6. 验证要求

纯函数用可控随机来源证明：结果来自整本剩余词书而非原先前 N 词；去重、排除完成词、数量不足、空候选、两个模式和非法模式均正确。不要用概率断言要求两次随机结果必须不同。

数据及组件检查：保存与放弃草稿、旧版本迁移、当日任务不变、刷新恢复、额外批次继承模式、全书耗尽、失败不落半任务、跨天、两个页面争抢创建、设置加载期间变化。

集成检查：现有七字段摘要仍通过当前本机服务，模式变化使旧请求过期；设置滚轮上滚修复、词表排序、复习入口、统计数量与新模式互不混淆。
