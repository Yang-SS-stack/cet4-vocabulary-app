# 导航层次优化设计

日期：2026-08-09
状态：已确认，待实施

## 目标

为四级单词学习网页建立清晰但克制的导航层次：左侧导航应有独立区域感，主学习区仍应是用户首先关注的地方。

## 使用场景与成功标准

- 用户在电脑端每天反复进入“今日学习”，需要快速识别当前位置和可去的页面。
- 导航栏与内容区一眼可区分，但不应像两张拼接的页面。
- 页面静止时应平稳、专注；鼠标经过导航时不应带动多个项目移动。

## 已选方向：书脊细线

- 导航栏使用比主内容区略深一档的暖纸色；主内容区继续使用现有暖纸底色。
- 两区交界采用“书脊”而非大面积渐变：一根金色极细线与一根低对比藏青细线并列。
- 保留纸张、藏青、金色和衬线标题的学习册气质，不改动页面名称和现有导航结构。
- 不使用明显的雾状或宽幅渐变，以免分界显得装饰化并削弱内容区的聚焦。

## 交互原则

- 当前页面：金色文字与固定的短线标记，状态必须持续可见。
- 悬停和键盘焦点：只做颜色与焦点环反馈，不发生文字或导航项位移。
- 点击导航：当前项保留轻微的向右伸展和标记线变长反馈，其他项目保持原位。
- 点击导航：继续由 React 更新当前页面；导航栏收起和恢复功能保持不变。
- 移除基于鼠标距离驱动的多项位移效果及其动画循环。
- 尊重系统“减少动态效果”设置；在该模式下保留所有状态信息，但取消非必要过渡。

## 实施边界

- 预计修改 `src/App.css`、`src/components/LineSidebar.jsx` 和 `src/components/LineSidebar.css`。
- 保持既有 React + Vite 架构、页面切换、测试环境和移动端紧凑导航。
- 不在本次修改中加入词卡、今日进度、学习按钮、词库或其他新功能。

## 验收标准

1. 桌面端导航栏与内容区有可见但克制的色阶区分和书脊细线。
2. 鼠标经过任一导航项时，其他项目不移动；当前项状态稳定可辨。
3. 键盘聚焦状态清楚可见，收起后仍可恢复导航。
4. 窄屏下导航继续保持紧凑横向布局，内容区优先显示。
5. 现有导航切换测试、代码规范检查和生产构建继续通过。
