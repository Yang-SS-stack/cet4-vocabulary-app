# 线上音频路径与音频索引按需加载设计

日期：2026-09-09

## 目标

修复 GitHub Pages 子路径下的音频 404，并把约 1 MB 的音频索引从首页主脚本中移出，同时保持现有词卡和发音功能不变。

## 已确认范围

- 音频地址根据 `import.meta.env.BASE_URL` 自动生成。
- 用户点击具体词书后才加载音频索引；首页和词书目录阶段不加载音频索引。
- 音频索引加载期间，词卡仍可读、可翻转，不因索引未就绪而报错或卡住。
- 索引就绪后，英音 Sonia、美音 Jenny、例句美音 Jenny 正常使用预生成音频。
- 保留播放中止、音频错误提示和浏览器语音兜底。
- 不改变搜索、排序、翻转、分页以及每页 21 张逻辑。
- 只在独立工作区和新分支中完成，不合入 `main`，不推送远程仓库。

## 方案

保留 `src/data/audioManifest.json` 和现有音频文件布局，新增一个音频索引加载边界：

1. 通过动态导入读取 JSON，使索引成为独立的构建资源，而不是进入首页主脚本。
2. 在加载完成后遍历索引中的音频地址，使用 `import.meta.env.BASE_URL` 生成可访问地址。
3. 在 `VocabularyPage` 选择具体词书时，与词库数据并行启动音频索引加载，并以请求编号防止用户快速返回/换页后旧请求污染当前页面。
4. 将已加载的音频索引传给 `WordCard`；索引为空时，`WordCard` 只传入空音频地址，现有 `SpeechButton` 自然继续使用浏览器语音。
5. 音频索引失败不阻断词库；词卡保留可读、可翻转和浏览器语音能力，预生成音频仅在索引成功时启用。

## 文件边界

- `src/data/audioManifest.js`：负责动态加载、缓存索引和根据基础路径转换音频地址。
- `src/data/audioManifest.test.js`：验证基础路径转换、索引结构和按需加载接口。
- `src/components/VocabularyPage.jsx`：在进入具体词书时启动索引加载，并把当前索引传给卡片。
- `src/components/VocabularyPage.test.jsx`：验证未进入词书不加载、进入后加载以及加载未完成时页面可用。
- `src/components/WordCard.jsx`：删除静态 JSON 导入，改为接收可选音频索引。
- `src/components/WordCard.test.jsx`：补充索引未就绪和索引就绪后的音频行为测试。

不改变 `SpeechButton` 的播放、中止、错误和浏览器语音逻辑；如测试需要，只验证它继续接收相同的 `src` 约定。

## 状态与错误处理

- `audioManifest` 初始为 `null`，表示尚未加载或正在加载。
- 索引成功后，卡片重新渲染并获得已转换的音频地址。
- 索引失败后保持 `null`，不显示新的阻断状态；浏览器语音仍是兜底。
- 词库加载和音频索引加载相互独立，任一失败不会让另一项失效。
- 词书切换、返回词书列表和组件卸载时忽略已过期的异步结果。

## 测试与验收

自动测试覆盖：

- `/audio/...` 在 `/` 基础路径下保持本地地址；
- 在 `/cet4-vocabulary-app/` 基础路径下变为 `/cet4-vocabulary-app/audio/...`；
- 首页、词书列表阶段不触发索引加载；
- 进入具体词书后触发一次可复用的索引加载；
- 索引未完成时词卡可显示、可翻转；
- 索引完成后英音、美音和例句获得正确地址；
- 索引失败时词卡不崩溃，浏览器语音仍可用；
- 原有搜索、排序、分页、翻转、发音和 21 张分页测试继续通过。

交付前运行 `npm test`、`npm run lint` 和 `npm run build`，比较修改前后的首页主脚本体积，并用生产预览手动检查本地音频地址。线上验收方法为打开 GitHub Pages 地址，进入词表和具体词书，在浏览器开发者工具的 Network 面板确认音频请求包含 `/cet4-vocabulary-app/audio/` 且返回成功。
