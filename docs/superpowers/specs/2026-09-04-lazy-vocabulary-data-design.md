# 词库数据按需读取设计

## 目标

将完整 CET-4 词库从初始页面脚本中移出。应用启动和展示词书目录时不读取词条；用户选择一本词书后，才读取对应的本地数据文件。

## 方案

词书目录仅保存 ID、显示名称、说明和数据文件地址。CET-4 与 CET-4 高频词汇各自使用一个 JSON 文件，放在 `public/data/`，由构建结果原样携带。

词书页面在点击词书时读取其 JSON 文件：

- 测试或调用方直接传入 `words` 时，沿用现有的同步展示方式。
- 正式词书只有数据文件地址时，显示加载状态，读取成功后按每页最多 21 条的规则展示。
- 文件不存在、网络响应失败或内容不是数组时，展示简短错误提示和返回词书目录的入口。

高频词汇改为自己的 JSON 文件，不再从完整 CET-4 词表中派生，避免任何正式页面入口重新导入完整词库。

## 保持不变

- 词书列表、词书名称、卡片内容和分页规则。
- 离线使用能力：JSON 与应用静态文件一起打包，无需连接外网。
- 测试中传入小型词表的方式，确保分页测试无需依赖文件读取。

## 验收

1. 进入词书页前不请求词库文件；选择 CET-4 后才请求其 JSON 文件。
2. 选择高频词书只读取高频 JSON 文件，且词频顺序不变。
3. 文件读取失败时用户能返回词书目录。
4. 生产构建中完整 CET-4 数据不再处于 JavaScript 资源；构建成功，测试和代码检查通过。
