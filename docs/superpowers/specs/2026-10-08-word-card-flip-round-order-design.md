# 词卡倒置闪现排查与每轮学习乱序方案

日期：2026-10-08。基线：main `75f6e21`。状态：用户已批准实施，并指定 Astra、中等推理强度；制作位于独立分支 `codex/word-card-round-order`，完成后预览验收，不自动合并或推送。下文排查记录保留开工前证据。

## 已确认的需求

1. 用户在 Edge 的大屏电脑上，点击词卡翻到详情背面时，短暂看到倒置的正面内容，然后消失。不是词表底部“下一页”按钮。
2. 已选中的今日学习词集需要每轮重新打乱，例如第一轮 acedb、下一轮 dbace。不是只在开始时打乱一次。
3. 保留既有词卡外观、配色与翻转效果，保留选词方式、学习进度、熟悉度和反馈规则。

## 排查证据与结论边界

### 词卡

- `WordCard.css` 正面独立旋转至 -180 度，背面从 180 度旋转至 none；两面使用 420ms 变换过渡与 backface-visibility:hidden。
- `WordCard.jsx` 翻转后立即同步 aria-hidden、inert、焦点和朗读可用状态。隐藏面只有 pointer-events:none；未由显式视觉状态在翻转交接后退出绘制。
- 在 Edge 154、2560×1440、像素比 1 与 2 的独立 4176 样本中，实际点击翻转及返回；完成后正面计算样式为 rotateY(-180deg)、opacity:1、visibility:visible，背面 transform:none。外层 `.fade-content` 仍保留 identity transform，来自 GSAP 的进场动画。
- 已保存翻转后截图，未捕捉到倒置闪现的瞬间。以上不是对 GPU 故障或特定 Edge 缺陷的确证。
- 初步假设：正反面翻转的背面剔除／绘制层交接出现短暂泄漏，外层残留变换可能参与。正面 opacity 和 visibility 的值本身符合现有 CSS，不能单凭这两项就断定浏览器错误。

浏览器规范参考：[背面可见性](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backface-visibility)、[Chrome 动画合成层](https://developer.chrome.com/blog/performant-expand-and-collapse)。它们解释镜像背面和动画层的机制，不证明本项目的确切根因。

截图位于本机 `.superpowers/sdd/card-flip-round-shuffle/work-card-flip-before-2560.png` 与 `work-card-flip-before-dpr2.png`。调试录制在前轮曾被自动审批拒绝，工具未给出具体原因；本轮没有重新尝试录制。

### 学习顺序

- 确切原因在 `selfAssessment.js:nextLearningItem`：从当前词在 itemIds 中的位置向后循环，返回第一个未完成／未移除的词。每轮都使用同一数组，因此顺序固定。
- `selection.js` 中的随机只负责从词书候选池抽取任务词集，并不安排后续各轮的出现顺序。
- `nextReviewItem` 目前复用同一函数；实现时必须将学习队列与复习调度分开，避免连带改变复习。

## 方案选择

### 翻页

推荐保留现有翻转，按单变量实验定位与修复：先验证外层进场动画结束后清除残留 transform 是否改变现象；若仍存在，再针对词卡翻转交接增加明确的视觉面状态及稳定的变换终态。每次只改变一个原因候选并比较，避免同时堆叠 GPU 样式。

备选是改为二维淡入淡出，能绕开三维背面绘制，但会改变用户原有翻转效果；不推荐。重新使用整个卡片 preserve-3d 旋转也不推荐，现有源码明确记录该结构曾导致 Chromium 背面滚轮命中问题。

成功标准：大屏 Edge 翻转不露出倒置文字；正面／详情往返、快速反向、详情原生滚动、文字选择、朗读、键盘及减少动态效果均保持正确。未在用户实际出现问题的环境中验证前，不宣称该瞬时渲染问题已根治。

### 每轮乱序

推荐保存“本轮出现顺序与当前位置”。覆盖今日学习和额外学习，每轮开始只将当前尚未完成的任务词打乱一次。每个词本轮出现一次；一轮结束后重新打乱仍需学习的词。超过一个可学习词时避免连续两轮完全相同；只剩一个时正常继续。

备选是每次随机挑下一词，改动较小，但可能连续出现同一词、其他词长时间不出现，不符合按轮学习。不采用只打乱初始 itemIds 的方案，因为它仍会固定重复一个顺序。

## 数据与交互规则

- `task.itemIds` 仍是已选定任务词集，不重抽词，不改变数量，不修改设置中的顺序／随机选词含义。
- 学习任务增加独立的 presentation 记录，保存本轮 order、index 和 round。order 是任务词 ID 的唯一子集；当前词与当前 index 一致，反馈期间可保留刚完成词，点击下一词时再推进。
- 进度与新队列在现有 change 写入中原子保存。保存失败、跨标签页冲突、日期变化或旧 token 均不推进队列；反馈修正仍作用于当前词。
- 刷新、退出再进入继续当前词与剩余顺序；不因重新渲染而再洗牌。全部完成时不再生成下一轮；完成或移除的词不进入新轮。
- 不以 knownCount 当全局轮次：答错或模糊会降低单词熟悉度，但本轮仍按队列走完，后续按原学习规则继续。
- 复习与错题调度保持既有规则，不增加设置开关或新页面组件。
- 需要保存新队列字段，采用 v8 数据格式，严格验证旧 v1–v7 后迁移。旧进行中任务保留当前词、视图、选项、反馈与熟悉度，当前固定顺序的剩余段先继续；下一轮再采用乱序。迁移不重写已保存反馈，也不丢弃历史任务。
- 新建任务从第一轮就乱序；随机源可注入，便于可靠验证。队列只在新建／换轮的受保护写入中生成，不放在 React 展示层。
- 摘要请求继续沿原七字段白名单；完整状态校验值包含队列变化。兼容性覆盖全局设置、每日任务、额外批次和历史记录。
