# 词表首次加载优化设计

## 背景

当前词书入口只保存整本 JSON 的地址。打开词书后，`loadWordBook` 会请求并解析完整数据，`VocabularyPage` 再在浏览器内完成搜索、排序和分页。CET-4 完整词库约 1.81 MB、4544 条，高频词库约 1.24 MB、2000 条，因此首次显示词卡前需要处理整本词库。

本任务只优化词库数据的运行时加载方式，不修改发音按钮、音频地址、音频清单或音频播放逻辑。

## 目标与非目标

### 目标

- 首次打开词书时优先显示当前页的完整词卡。
- 中英文释义和词性搜索仍覆盖整本词书，并沿用现有匹配语义。
- 保持字母排序、词频排序、每页最多 21 条、翻卡、例句、词组和发音接口行为。
- 缓存当前会话已加载的清单、搜索索引、详情分片和正在进行的请求。
- 为首次加载、后台索引、页面分片和失败场景提供明确状态；已有可展示内容不被后台加载状态替换或阻塞。
- 保持现有 React、Vite、组件和测试结构，只做词库加载链路所需的局部调整。

### 非目标

- 不修改 `SpeechButton`、音频地址生成、`audioManifest.json` 或音频播放逻辑。
- 不引入 IndexedDB、Service Worker、服务端 API 或新的状态管理框架。
- 不删除旧的完整 JSON；旧文件继续作为构建源和回退材料，但不再由运行时词书入口请求。
- 不改变词条内容、词频数据、排序规则或搜索结果语义。

## 方案选择

### 采用：词书清单 + 轻量搜索索引 + 默认排序详情分片

每本词书生成独立的运行时目录：

```text
public/data/word-books/cet4/
  manifest.json
  search-index.json
  chunks/000.json
  chunks/001.json
  ...

public/data/word-books/cet4-high-frequency/
  manifest.json
  search-index.json
  chunks/000.json
  chunks/001.json
  ...
```

`manifest.json` 保存总词数、默认排序、首屏词条编号、搜索索引地址和详情分片地址。`search-index.json` 每条只保存单词、中文释义、词性、词频和详情分片编号，不保存音标、例句、翻译和词组。`chunks/*.json` 保存现有完整词卡字段。

详情分片按约 128 条生成。CET-4 按字母顺序生成，高频词书按词频顺序生成，使两本词书的默认首屏都集中在首个分片中。切换另一种排序或搜索时，只请求当前结果页所需的详情分片。

### 未采用的方案

只按首字母拆分的实现较简单，但单个字母仍可能较大，且高频词书按词频排序时首次页面可能需要请求多个分片。浏览器数据库或 Service Worker 会引入超出本任务范围的缓存和发布复杂度。

## 数据生成与运行时接口

新增一个数据构建脚本，从现有 `public/data/cet4.json` 和 `public/data/cet4-high-frequency.json` 生成运行时资源。旧 JSON 保留，方便重新生成和回退；运行时 `wordBooks` 改为指向新目录中的 `manifest.json`。

`loadWordBook` 继续作为词书入口，但返回一个按会话复用的词书会话对象，而不是要求调用方一次性持有整本词条。会话至少提供以下能力：

- 加载默认首屏详情；
- 按排序方式、页码和搜索词读取当前页；
- 暂存搜索索引加载状态；
- 按详情分片缓存完整词卡；
- 复用相同词书、索引或分片的已完成请求和进行中请求。

为保留现有测试中直接传入 `words` 数组的方式，页面层继续支持内存词书适配器。这样分页、排序和卡片测试不需要依赖生成后的静态文件。

## 数据流

### 首次打开

1. 用户选择词书。
2. 读取 `manifest.json`。
3. 读取首屏详情分片，并同时在后台开始读取 `search-index.json`。
4. 首屏详情分片完成后显示词卡，不等待搜索索引。
5. 搜索索引完成后，搜索输入和结果统计转为可用状态。

### 无搜索词的翻页和排序

- 无搜索词时，从索引中的排序结果取得当前页词条编号。
- 根据词条编号分组请求所需详情分片。
- 分片已缓存时直接显示，不重复请求。
- 切换排序后将页码重置为第 1 页，保持现有行为。

### 搜索

- 搜索索引加载后，继续使用现有 `matchesWordQuery` 处理英文拼写、中文释义和词性别名，避免改变 `n.`、`vt.`、`不及物动词` 等已有语义。
- 先在整本索引上得到准确匹配结果，再按当前排序切片。
- 只加载当前结果页对应的详情分片；不使用其他词条填充 21 条。
- 结果数量、空结果提示和搜索后分页继续遵循现有界面行为。

## 缓存与并发

缓存分三层：

1. 词书会话缓存：同一会话中重复进入同一本词书时复用清单、索引状态和分片缓存。
2. 搜索索引缓存：每本词书只请求一次，并保存进行中的 Promise，避免并发搜索产生重复请求。
3. 详情分片缓存：以词书和分片地址为键保存已完成或进行中的请求。

选择另一本词书时不清空其他词书缓存；返回词书列表只清除页面选择状态，不清除会话缓存。

## 加载与失败状态

- 没有任何可展示词卡时，显示现有的整页首次加载状态。
- 已有词卡时，翻页、搜索或后台索引加载使用局部状态提示，不隐藏已经可展示的词卡。
- 清单失败、首屏分片失败、搜索索引失败和详情分片失败都进入明确的错误状态，并保留返回词书入口。
- 搜索索引失败时不伪造搜索结果；词卡浏览仍可继续，搜索区域显示不可用原因。
- 过期请求不得覆盖用户随后选择的词书、排序、搜索词或页码。

## 测试策略

每完成一项功能补充对应测试：

### 数据资源测试

- 两本词书的清单总数正确。
- 搜索索引覆盖全部词条且单词唯一。
- 每个索引词条都能映射到详情分片。
- 详情分片保留现有完整词卡字段和高频词频数据。
- 默认排序首屏编号能加载出 21 条以内的正确词卡。

### 加载会话测试

- 首屏详情分片可以在搜索索引尚未完成时先返回。
- 相同词书、索引和分片不会重复请求。
- 搜索会覆盖整本索引，并只读取当前结果页所需详情分片。
- 中文、英文和词性搜索结果与现有 `matchesWordQuery` 规则一致。
- 清单、索引和详情分片失败时返回可识别错误。

### 页面测试

- 首屏词卡不等待后台索引。
- 搜索不会用无关词条补满结果页，结果可以少于 21 条。
- 字母排序、词频排序、翻页和部分末页保持现有行为。
- 已加载页面再次访问不触发重复请求。
- 已有页面内容在后台加载时仍可展示，失败提示不会破坏返回词书流程。

现有 `WordCard`、`SpeechButton` 和音频相关测试保持不变；基线中已有的 `audioManifest.test.js` 超时问题单独记录，不在本任务中修复。
