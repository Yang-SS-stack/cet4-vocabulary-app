## 1. 交付与基线

用户输入“今天有 20 分钟，想保持备考进度”，程序自动读取当前学习摘要，模型提出本次学习安排，展示数量、顺序、时间估算与依据。结果始终是草稿；用户可以据此手动学习，本阶段不提供采纳后修改设置或任务的功能。

2026-10-09 本机 main 为 `b46389224716052de39e567b89a8d652a31d5b35`；浏览器数据版本为 8，已包含侧栏／选词模式和单词卡片／每轮随机展示顺序。现有维护页及今日、统计、设置、词表界面已获用户验收。本轮未重新核查远程发布，也未重跑产品测试。实施从届时最新 main 隔离制作，保护所有后续已验收改动。

浏览器依旧是学习记录、任务、反馈、更正和排程的权威来源。本机 Python 服务仅验证摘要并组织模型请求，不能直接读浏览器存储。P-03-C 独立实现确认与应用；P-05 独立实现开放对话和工具；本轮不建完整学习数据库、不扩展题型或逐词诊断。

## 2. 方案比较与建议

| 方式 | 用户感受 | 代价与适用性 |
| --- | --- | --- |
| **A：现有弹窗内按时间与目标生成一次草稿（推荐）** | 打开建议，输入需求，点击生成，看数量与依据 | 符合本轮范围，复用已验收页面；调用由用户主动触发 |
| B：独立聊天页、多轮追问 | 自由讨论，再整理计划 | 对话历史、上下文和调用控制明显增加，属于 P-05 |
| C：每次进入今日学习自动生成 | 少一个点击 | 容易在刷新、切换时重复消耗额度，且需求时间可能未确定 |

本方案采用 A。模型负责在已知约束内选择安排；程序负责边界、数学计算、依据展示和失效保护。

## 3. 学习页怎样使用

本节描述最终行为；当前只审核并制作模拟 UI，不产生以下真实调用。详细位置、动效、模拟场景及桌面／手机验收以第一阶段 UI 文档为准。

1. 原“学习建议”入口仍打开居中弹窗；背景页面不被撑长，保留锁定背景滚动、关闭动效、键盘操作与焦点返回。提议将原两标签调整为“规则建议／AI 建议／依据”，默认规则建议。
2. “AI 建议”页顶部为紧凑输入区：可用时间（整数 1～240 分钟，默认当前每日时间；未设置时显示 20 分钟并允许修改），学习目标（可选，最多 200 个字符，默认“保持当前备考进度”）。时间直接填写或 10／20／30 分钟短选项选择，不新增设置页滚轮改造。
3. 输入区说明“仅发送学习汇总与本次需求”；完整范围在“依据”页查看。提示用户避免在目标中填写身份、联系方式或秘密。
4. 初始仍可看现有规则建议；**打开、切标签、修改输入、刷新均不调用模型**。点击“生成建议”才发送一次请求。生成中显示等待和取消；按钮禁用以防连点。
5. 成功后显示“模型建议 · 草稿”：本次新词与复习数量、推荐先后顺序、程序计算的约数分钟；最多三条简短理由。另保留明确标注的当前规则建议作对照，不混用“每日安排”与“本次安排”。
6. “依据”页保留本地事实，追加本次使用的汇总依据与估算说明；原任务和逐次事件对账仍仅在浏览器显示。模型没看到逐词明细，不宣称找到了具体薄弱词或客观掌握率。
7. 失败显示短原因及“当前显示规则建议”，用不同来源标识。模型停用、未配置、未连接时，规则建议仍可查看，不用阻断手动学习。
8. 更改时间／目标后，旧结果标为待重新生成；关闭弹窗取消正在等待的请求并清空该草稿。跨天、换书、学习／更正／设置或其他标签页记录变化时，旧草稿失效。刷新后不恢复模型草稿。
9. 手机沿用受视口限制的弹窗，输入和指标窄屏排列，必要滚动限于弹窗内部；保持背景位置。尊重减少动画设置。

本轮按钮只有生成、取消、关闭及依据切换；“应用计划”留到 P-03-C。不因建议量变化重建已经存在的当天任务。

## 4. 接入与私密配置

- 服务：阿里云百炼，华北2（北京）；固定 `qwen3.7-flash-2026-07-15`，禁止静默换别名或其他模型。
- 使用普通文本请求、非思考模式 `enable_thinking=false`，结构化字段输出 `response_format=json_schema`。无联网搜索、工具、图像／视频、批量或部署服务。本阶段复用已锁定的 httpx，不新增模型 SDK。
- 默认固定调用地址 `https://dashscope.aliyuncs.com/compatible-mode/v1/chat/completions`；如当前业务空间要求专属 API Host，配置时核对官方地域接入信息，限于对应北京域名与固定路径。浏览器和模型输出不能指定请求地址；关闭重定向，不从客户端读代理配置。
- API Key（模型访问密钥）仅保存于当前用户目录 `%LOCALAPPDATA%\LinguaJet\p03b\model-config.json`，由用户私下填写；不放 Git、前端、聊天或终端命令参数。配置包含 key 和经审核的北京 API Host，格式严格校验，界面只报告“已配置／未配置”。模板用空值，运行配置始终在仓库外。
- 启动服务默认禁用模型，获批后提供明确启用方式；配对及摘要校验继续可用。读取私密配置和日志时不输出原始内容、密钥前后缀或异常全文。用户自己在百炼配置／轮换密钥；需要新建密钥时再逐步指导，不在本轮创建。
- 官方结构化输出文档建议避免 `max_tokens` 以防截断。本方案为控制每次输出，提议设置 `max_tokens=1024`；因此必须将截断和非 stop 结束当作失败，不修复、不重试、不把半份建议展示为成功。该取舍纳入真实样本验证；若不兼容，暂停此项并提交参数调整，不静默取消限制。

接口格式与能力依据：[结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)、[模型信息](https://help.aliyun.com/zh/model-studio/qwen3-7-flash)、[混合思考模式](https://help.aliyun.com/zh/model-studio/deep-thinking)、[密钥及北京接入](https://help.aliyun.com/zh/model-studio/get-api-key)。以上在 2026-10-09 只读核对，未执行模型调用。

## 5. 发送字段与数据边界

浏览器→本机服务沿用现有 Facts v1 的七项 settings 白名单及完整摘要，并新增本次时间和目标。本机→百炼再次明确选取以下内容，不直接转发完整请求：

| 分组 | 可发送字段 |
| --- | --- |
| 本次需求 | availableMinutes、goal |
| 日期与目标 | basis.localDate、settings.examDate |
| 当前词书 | book.id、label、totalWords、completedWords；剩余量由程序按总量与完成量计算 |
| 每日安排 | settings.dailyNewWords、dailyReviewWords、dailyStudyMinutes |
| 今日任务 | today.learning、review、extraLearning 的词书标识、分配／完成／剩余数量；额外批次数 |
| 复习负担 | reviewLoad.wordBookId、dueCount、outsideTodayTaskCount、needsReconciliation |
| 今日及最近七天 | 两个 period 的日期范围、词书标识、completions、selfAssessments、choices、corrections、effectiveSelfAssessments、coverage、issues |
| 规则建议 | ruleRecommendation 中已定义的数量、日期剩余、时间估算与超限标记 |

不发 pronunciation、mistakeStudyWords、newWordSelectionMode、逐词及每轮顺序、itemId、taskId、feedbackEvents、本地 evidence、raw snapshot、全历史、generatedAt、timeZone、snapshotToken、factsToken、requestId、任何会话凭据或密钥。后端可使用这些本地绑定信息验证请求，但不把它们加入提示词。词书标识只是已批准进度摘要的关联字段，不是访问凭据。

用户目标与词书文字均作为资料，不能覆盖程序指令。null 保持“未知”，缺失不能改成零；更正后有效自评、选择作答与原记录分别标注。没有事件不表示没有学习，未能证明完整的事件历史不支持“完整准确率”或掌握率断言。

## 6. 本机接口与建议字段

新增 POST `/api/v1/advice/draft`，不更名 `/facts/check`。请求字段固定为 `adviceContractVersion=1`、`facts`（现有严格 Facts v1）、`intent={availableMinutes,goal}`。使用 facts.requestId 作为本次请求标识；相同请求标识必须绑定相同输入，重复使用不同输入返回冲突。

新增 GET `/api/v1/advice/status` 仅报告配置／启用状态、固定模型名称、本项目调用计数、用量是否已取得、已知额度错误及控制台核查入口。无密钥、目标、学习摘要、私密路径或伪造的实时余量。两个接口与预检继承固定 Host、Origin、Sec-Fetch-Site、内存会话、拒绝未知路由和查询参数、no-store 保护；status 也必须认证。

模型原始输出仅允许：

- `newWords`、`reviewWords`：非负整数，各 0～100，另受后端计算的更小可用上限限制。
- `order`：review-first、new-first 或 balanced；数量全零时只能 none。
- `reasons`：1～3 个 `{code,evidenceRefs}`，code 只允许 time-budget、due-review、today-remaining、exam-gap、recent-feedback、insufficient-data；引用只能是明确的已发送事实路径。

理由由程序根据模型选中的代码和核验后的事实生成短句；模型不输出任意事实数字或逐词诊断。recent-feedback 只能解释为本次已记录自评情况，不等于客观掌握率。exam-gap 需未来考试日期且可计算；due-review 需已知正数；insufficient-data 必须存在未知或覆盖缺口。

返回给网页的草稿由后端补充 requestId、draftId、当前词书、依据日期、两个绑定 token、receivedAt、intent 与 source=model、校验后的数量／顺序、程序估算和已核验理由、warnings，以及 usage 的输入／输出／总量（未取得为 null）。生效含义固定为“今日的本次安排建议”，不是设置生效日期或已创建任务。期限标记为收到后五分钟，且只要依据变化立即失效。

所有原始模型字段额外禁止未知键、真假值冒充整数、非有限值、超长数组和引用不存在的字段。原始响应限 64 KiB，解析拒绝重复键及无效 JSON；不用文本截取方式拼接／修复 JSON。

## 7. 数量、时间与业务校验

1. 生成本次可用上限：已有当前词书今日学习任务用其 remainingWords；任务不存在时用每日新词设置及当前剩余词量；已有任务是空／已完成时上限为 0，不重建。额外学习仅作为依据，不自动添加批次，也不算作本次建议新词上限。未知设置或词量导致上限不可确定时暂停模型，显示数据不足与规则状态。
2. 复习已有当前词书任务用其 remainingWords，任务不存在时用 min(每日复习设置,当前到期量)，最大 100；数据需要对账或未知时停止量化建议。已有任务与当前选书不一致时明确提示先核对任务词书，不跨书建议、自动换书或写设置。
3. 模型数量必须分别不超过 0～100 硬范围及本次上限；越界直接拒绝，不静默截断成合法值。
4. 与现有程序一致：新词按每词 60 秒、复习每词 20 秒，合计向上取整至 5 分钟。建议约数分钟不得超过用户的 availableMinutes。小于 5 分钟可用时间时显示“当前公式无法给出非零安排”，允许零量结果；不夸大精确度或个人效率。
5. 校验理由代码的前提与引用存在性；最终理由数字由程序取值。缺失、冲突、不适用数据不能成为确定依据。结构校验不能证明安排最优，用户仍需判断建议是否合适。
6. 本轮只保证草稿不修改正式状态。保护三次认识、复习默认进度不算真实反馈、四轮完成、相邻复习间隔、跨天、更正与冻结任务、选词模式及数据版本 8；不升级学习数据结构。

## 8. 请求、取消与失效

| 项目 | 提议参数与行为 |
| --- | --- |
| 请求大小 | 浏览器本机正文 256 KiB；发送百炼的完整请求正文不超过 24 KiB，超过时本地拒绝，不按字数冒充准确 Token 数 |
| 等待 | 服务端模型操作总时限 30 秒（包含响应体读取），连接阶段最多 5 秒；网页总等待 35 秒，含解析；摘要／配对原等待不变 |
| 并发 | 后端全局仅 1 个生成中操作；客户端生成期间不能同时发维护检查；另一标签页请求返回忙碌，不排队 |
| 去重 | 同一 requestId 在同一有效会话五分钟内仅调用一次，同标识不同输入拒绝；相同 factsToken＋时间＋目标的进行中请求返回忙碌，成功结果五分钟内复用并重新验会话与依据。已明确失败的请求保留其标识记录，新 requestId 可由用户手动重试；取消／超时仍受原等待窗口限制 |
| 手动重试 | 禁止自动重试、自动修复及自动切模型。明确失败后用户可主动重新生成；新请求重新取摘要并核对当前限制。取消／超时的上游结果未知时至少等待原 35 秒窗口结束再允许新调用 |
| 取消 | 点击取消、关闭、离开页面、依据变化停止前端等待；服务端尽可能检测断开并取消上游，不能承诺供应商撤回已受理调用或退回 Token |
| 迟到返回 | 接收后校验会话有效、请求标识与输入绑定、词书、日期、snapshotToken／factsToken；并确认当前操作代次。过期、已取消或变更后的结果不展示为当前建议 |
| 中途过期 | 发起和返回时均验证会话。过期需重新配对；即使生成完成也不交付给过期会话，不重用旧凭据 |

服务端五分钟去重缓存只在内存保存必要键、状态与结果；保留至 TTL 到期、服务端会话过期／替换或服务停止，最多 20 条，满时移除已结束最旧项，不移除仍在生成的项。前端断开立即丢弃本地结果与凭据，后端不能仅凭页面状态推定会话已被撤销。浏览器快照 hash 用于一致性绑定，不能证明学习真实或授权其他操作。

## 9. 免费测试、额度与用量

**已批准：测试付费预算 0 元，仅使用固定版本免费额度。** 用户截图确认模型剩余 100 万 Token、到期 2027-01-07、“用完即停”已开；这是当时状态，不是未来实时余额。无付费测试或充值。

提议额外调用限制：服务端每分钟最多 2 次、每天最多 20 次、P-03-B 本次验收合计最多 100 次真实上游尝试；日界以 Asia/Shanghai 计算。首次真实样本批次为最多 5 次（常规、短时间、复习较多、缺失记录、重复触发），执行前展示样本和允许发送范围并取得用户启用。其余自动检查均用模拟网络。

尝试次数在发送前原子占用；失败、取消、用量未知和无效输出均消耗一次尝试，不因重启清零。用 Python 标准库 SQLite 保存最小计数到 `%LOCALAPPDATA%\LinguaJet\p03b\usage.sqlite3`；单例启动／文件锁保护，状态损坏或写入失败时禁用模型，不假定消费为零。测试总次数只在另行批准进入新阶段时调整，不提供网页清零按钮。

准确余量采取已核实的控制台核查方式：真实测试每轮前后、任何失败后，刷新固定版本额度页，记录 remainingTokens、expiresOn、checkedAt 和来源“控制台／用户截图”；逐步人工操作仍一次一步。报告保存这些额度证据，不把截图中的账号信息抄入文档。查询入口不携带敏感参数。

收到 `403 + AllocationQuota.FreeTierOnly` 显示“该模型免费额度已用尽，请在百炼核对余量与有效期；当前使用规则建议”。确认过期时另列过期原因；只有普通 403、429、超时或断网不足以判断耗尽。失败后仍有余量须明确告诉用户“额度仍有剩余，继续排查本次错误”；查不到则报告“暂时无法确认剩余额度”。明确额度耗尽／过期后服务停用模型，待用户核对恢复条件，不能自行关闭用完即停。

目前未核实可用推理 API Key 查询准确免费余额的官方接口。`models/limits` 是频率／周期限额，不是免费余额；本项目累计 Token 也不等于账号共享后的剩余量。status 返回 `remainingFreeTokens=null` 与“需控制台核查”，不制造自动查询成功。新增官方接口或读取控制台私有接口不在本轮范围。

每次 usage 若有效，记录实际输入／输出／总 Token；无 usage 标为“未取得”，保留占用次数并提示复查控制台。按公开单价计算的金额只能标“未抵扣前估算”，不是实际扣款；本轮优先展示 Token，不用历史价格伪造实时账单。0 元依赖百炼端当前正确模型的用完即停，本机计数不能代替该保护；若开启状态无法核实，暂停真实样本。

官方依据：[额度规则与更新延迟](https://help.aliyun.com/zh/model-studio/new-free-quota)、[具体错误码](https://help.aliyun.com/zh/model-studio/error-code)、[限额接口](https://help.aliyun.com/zh/model-studio/list-quotas)。额度耗尽分支用模拟错误验证，不能故意烧完免费额度。

## 10. 诊断、保存和失败回退

模型草稿不写 localStorage 或磁盘，后端仅五分钟内存缓存；页面关闭／刷新即清空。后端计数库只有 attemptId、时间、阶段、本地标准结果码、模型固定名和可用的 Token 数，不保存目标、提示词、摘要、模型原文、用户凭据或 hash。每日计数及本次验收累计值保留至阶段收尾；操作明细最多 30 天，启动和新增时清理，累计值不能因清理被重置。

维护页延用最近 20 条内存诊断，追加“模型建议”项目、成功／失败／取消／依据过期、耗时、请求编号、标准错误类别及用量取得状态。复制报告仅包含白名单，不含上游原始 message、密钥、路径、目标和事实内容。用户提供的额度值留在测试验收报告，不自动持久化进学习存储或伪装实时。

访问保护失败、输入非法或依据已变化不调用模型。模型未启用／未配置、网络／等待失败、身份或余额错误、频率限制、免费额度不可用、次数达限、非法或越界建议、截断、虚构引用等均给固定中文提示；前端从当前有效事实生成明确标注的规则回退。规则也无法计算时诚实显示“无法计算”，不提供编造数量。

## 11. 验证与人工验收安排

**第一阶段先验收 UI**：仅模拟输入、等待、结果、取消、失败、额度提示与失效；预览有“演示数据”标识，不读写正式学习存储、不连接 Qwen。覆盖桌面／手机、焦点、悬停、减少动态效果及背景不延展。按一次一个操作进行人工验收，不重复已通过的原 UI 或 P-03-A 检查。第一阶段通过后，提交第二阶段更新方案并单独审核。

**第二阶段功能方案获批后**，自动验证按行为检查，不重演已通过 P-03-A 人工验收：

- 输入、上游发送白名单、严格输出、业务关系、未知与冲突、任务词书不一致、数量硬限、估算及理由前提。
- 固定模型、非思考、无工具／搜索、地址限制、私密配置脱敏、无效 JSON／截断／大响应、30 秒全程超时。
- 一次真实尝试、并发和去重、失败不自动重试、取消仍占次数、重启保留计数、状态库异常拒绝调用、用量未知及清理不重置累计。
- 额度耗尽、过期、额度核查失败、仍有余量的网络错误、普通 403 与 429 区分、免费保护未核实时不启用真实样本。
- 前端假响应错标识／错 hash、目标变化、跨天／换书／学习／更正／跨标签页／过期会话、关闭与迟到结果、焦点与手机布局。
- 端到端操作前后学习存储一致；仅正常人工学习可修改。原学习、复习、更正、设置冲突、顺序／随机选词和每轮展示不被破坏。

修改完成后执行相关前端与后端检查、必要全量检查、lint、生产构建与版本核对。纯设计文档当前不运行产品测试。预览必须能从已允许的 Origin 联调本机后端；不为了本地预览放宽生产来源或发布旧分支。需要更新在线前端时，在实现可审查且检查通过后单独取得发布授权。
