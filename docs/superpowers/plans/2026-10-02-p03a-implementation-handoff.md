## 2. 最新决定与旧规划冲突

本对话的新决定依次为：

1. GitHub 在线页面继续作为日常学习入口，不运行本机前端，不处理旧 localhost 记录同步。
2. 开发阶段 Python 后端在本机运行，由 GitHub 在线页面直接连接验收；以后云端后端另审。
3. 导出导入失去本阶段必要性，因此从 P-03-A 取消；不把手动搬运记录当助手前置步骤。
4. 使用 Edge；需要验证本地网络访问权限的允许、拒绝和恢复。
5. 接受开发阶段一次性连接码：服务启动后配对，随后请求自动发送摘要；刷新、连接过期或重启后重新启动并配对。

R2 取代 R1 的本机网页、真实迁入、两个入口交接、cookie 同源会话、独立 local 构建和迁移验收。2026-10-02 后续整体规划和执行检查表已同步新路线，Obsidian 拟追加内容仍待确认；不能把旧文字当作恢复旧安排的授权。用户再次确认先完成单人版再单独设计云端部署。整体规划的技术职责、配置和可见验收说明已对齐 R2 第 7.5 节，当前完整详细稿与参数仍未批准。[实施流程确认卡](2026-10-02-p03a-execution-approval.md)汇总本次批准范围。管理员身份、后端权限及只查看状态/失败/用量的管理页面归 P-09-A 上云前准备，不并入 P-03-A。拟追加记忆的具体文字见 docs/superpowers/specs/2026-10-02-linguajet-obsidian-roadmap-update-proposal.md，确认前不写入长期记忆。

源码在 main/远程仓库，个人学习记录在浏览器原站点的 localStorage，不能混为一份数据。后端接收前端主动发送的摘要，不直接读取浏览器。其他访客页面里的 127.0.0.1 指访客自己的设备，不是开发者的电脑。

## 5. 不可改变的边界

- 学习完成 3 次、复习初始 2/完成 4、更正撤回、原间隔排程、固定任务、跨日与积压沿用 P-01/P-02。
- 默认进度不是实际反馈；原始自评、选择结果、更正和有效自评分开；无法证明旧事件完整性时明确提示。
- 当前书与今日任务书可不同，不混合进度；近 7 天按本地日历日期，复习用词次。
- 浏览器为学习状态唯一权威，后端只处理摘要；不新增学习写接口、历史数据库、同步、备份/恢复或迁移。
- 规则建议复用 recommendations.js，缺值不补 0，不自动应用，不在 Python 复制一套排程算法。
- snapshotToken/factsToken 只标识依据，前端严格校验响应时依据仍有效；不上传事件/任务全文或具体错题。
- 开发区默认关闭，普通在线访问不自动向环回地址请求；连接失败不影响原学习功能。
- CORS 预检不要求 Bearer；业务请求必须认证。禁止来源不获 CORS，合法来源的错误响应保留 CORS。
- 不沿用 Sec-Fetch-Site same-origin、SameSite=Strict cookie 或“Pages 关闭所有本机功能”的 R1 设计。
- 不关闭 Edge 安全机制、修改企业策略/注册表、开启公网监听或隧道；失败先核实并询问。
- 模型 P-03-B、采纳 P-03-C、完整统计 P-04-B；RAG、出题、云端账号/数据库均不顺带实现。

## 8. 用户验收与学习交接

用户操作按 R2 第 8.4 节：原在线记录对账 → 启动/连接/允许权限 → 当前摘要成功 → 非法示例拒绝 → 刷新记录保留且需重连 → 停止后端后正常学习。所有结果在页面可看；不要求用户先学习完整后端或搬运个人数据。

复盘只解释“浏览器记录 → 前端生成摘要 → 后端访问认证/输入校验 → 页面显示”，运行合法和非法输入并指出没有写学习记录的位置。在独立学习项目核对 L 编号和进度；本任务不更新它或 Obsidian。

本机配对与将来账号验证分开。正式云端的登录、数据归属/授权、HTTPS、费用和运营验证待单独方案；P-03-B 密钥、供应商、发送范围和失败回退同样未决。
