## 2. 确认后的实施顺序

### 第一步：准备隔离工作区和可执行计划

- [ ] 核对批准回复、主分支、工作区和已有隔离目录，保留全部现有草稿，不覆盖其他工作。
- [ ] 复用合适隔离工作区或创建本项工作区，准备独立逐文件实施计划，列出模块接口、必要测试和阶段检查。
- [ ] 先只读核对 Python 与依赖兼容性；项目所需依赖安装到隔离环境，不修改工具运行环境。

可检查成果：实施计划、准确文件范围、执行环境说明。发现与批准稿不一致的条件时先询问。

### 第二步：A1 事实和规则建议

- [ ] 先用合成样本验证统计口径，再增加一致的只读快照和纯事实投影。
- [ ] 实现今日/近 7 天、当前词书与固定任务分栏、到期负担、实际反馈和更正对账、旧历史缺失说明。
- [ ] 复用现有规则建议，加入浏览器内证据；不创建任务、保存设置或更改排程。

可检查成果：事实数值与明细一致；覆盖默认复习进度不算反馈、两类更正、额外批次、异书、跨天、历史缺失、冲突和无数据。

### 第三步：A2 本机后端

- [ ] 实现健康、配对、摘要检查三个 API，配对和摘要检查均严格验证输入。
- [ ] 实现固定监听/来源、一次性连接码、内存会话、预检、限额、统一错误和脱敏日志。
- [ ] 加入前台启动/停止脚本与依赖锁定，正常启动不反复联网安装。

可检查成果：合法输入通过；非法输入、来源、凭证、超限被拒；摘要不落盘，无数据库及模型调用。

### 第四步：A3 页面联动

- [ ] 接入事实面板、默认关闭的开发连接区、权限说明与状态反馈，保持现有界面风格。
- [ ] 实现“检查当前学习摘要”和“检查非法示例”，用户不用填写或搬运学习数据。
- [ ] 实现内存凭证、超时取消、依据变化及迟到结果保护；断开、刷新、失效均按已确认流程处理。

可检查成果：页面显示检查结果；固定非法示例与真实数据分开；换书、跨天、反馈和跨标签变化不会让旧结果冒充当前成功。界面可用键盘和窄屏操作。

### 第五步：A4 代码验证与发布审核

- [ ] 完成聚焦测试，再运行全量前端测试、lint、Pages 基础路径构建及后端测试，结果只填实际输出。
- [ ] 检查原学习/复习/更正/音频回归、发送白名单、日志和只读存储；破坏性用例仅使用合成数据或隔离资料。
- [ ] 交付可审查变更、测试结果、界面和线上更新/回退安排，再请求单独发布授权。

可检查成果：本地代码验证报告。此次批准可启动产品实现，不自动授权推送 main；当前推送 main 会更新 GitHub Pages，属于发布动作。

### 第六步：获准发布后真实在线验收与交付

- [ ] 从原 GitHub 在线页面在实际 Edge 验证权限允许/拒绝/恢复、连接、真实摘要、固定非法输入、失效/重启、停服回退和资源路径。
- [ ] 用户核对真实学习记录；提供启动/停止手册、逐按钮验收清单、实际证据与学习复盘卡。
- [ ] 单独记录自动检查、真实浏览器检查、用户验收和未完成项；用户验收完成后再进入 P-03-B 方案。

完成标准：原记录和规则保持、事实能对账、合法摘要成功、非法输入被拒、停止服务仍可手动学习、全部必需自动及在线检查通过。未获发布授权或未完成真实在线验收时，仅报告“代码验证完成，真实在线联调待完成”。
