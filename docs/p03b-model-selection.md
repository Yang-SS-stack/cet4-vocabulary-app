## 新增验收项：免费额度核查与失败提示（2026-10-09 用户要求）

用户要求测试增加“查看剩余免费额度”，且测试失败时须检查是否额度已用尽并提示用户。此项纳入完整 P-03-B 方案及实施交接卡：

1. 每轮真实测试开始前、结束后，以及任一真实测试失败后，核查北京地域固定版本 `qwen3.7-flash-2026-07-15` 的剩余免费额度、到期时间与用完即停状态。记录数值、核查时间和来源；控制台数值分钟级更新，需要刷新，旧截图不视为本次实时查询。浏览器未连通时可由用户提供当前页面证据，人工操作仍一次只给一步。
2. 服务端按供应商返回的具体错误码区分原因。`403 + AllocationQuota.FreeTierOnly` 对应免费额度不可用，界面明确提示“该模型免费额度已用尽，请在百炼控制台核对剩余额度与有效期；当前使用规则建议”，测试报告同时记载服务端错误证据和控制台核查结果。仅有 HTTP 403 不足以判定额度耗尽。
3. 发生超时、网络错误、认证失败、限流或输出校验失败时，同样检查额度作为排查步骤；提示实际已知原因。额度有余量时明确记录“额度仍有剩余，当前失败需另行排查”。核查失败时提示“暂时无法确认剩余额度，请在百炼控制台核查”，不能填零或断言耗尽。已有额度耗尽错误证据仍可提示该错误，但余量数字与过期原因不能编造。
4. 精确余量本轮按控制台读取。2026-10-09 查阅的官方文档明确提供控制台查询路径；尚未核实适用于此模型、可通过现有推理 API Key 读取免费余额的公开接口。`GET /api/v1/models/limits` 返回请求频率和周期 Token 限额，不是剩余免费 Token。每次调用返回的 usage、本项目累计消耗及截图基线相减，也不代表账号所有来源共享后的实时余量。若后续找到适用官方接口，须先补充具体接口及权限设计再纳入方案，不调用控制台私有接口或索取控制台会话凭据。
5. 自动验证覆盖额度耗尽错误、额度仍有余额的其他故障、查询不可用、过期及普通 403 等分支，采用模拟响应，不为制造耗尽场景实际消耗 100 万 Token。真实测试保留每轮额度核查，失败报告必须包含额度状态（有余量／耗尽／过期／无法确认）、证据来源和处理结果。停止自动重试；不切换模型、关闭用完即停或自动充值。

## 场景与选择依据

P-03-B 读取已有摘要，结合用户的时间和目标，生成带数量、时间估算、理由与事实依据的建议草稿。后端校验结构与业务约束，失败时明确回退到规则建议。应用设置属于 P-03-C；本轮不自动写学习反馈、任务、排程或设置。

结构化输出指按预先规定的字段返回结果，便于程序检查。支持这种能力不表示建议必然正确，数量、日期、词书与事实依据仍须由后端验证。

本次推荐依据是公开接入能力、计费和阶段范围，不是三家模型在本项目中的实测质量排名。正式样本评估留到模型、发送范围与预算获批后。

### 费用计算示例

假设每次输入 2,000 Token、输出 600 Token，调用 100 次，无缓存、无重试、无额外计费推理或工具：

- 千问：`100 × (2000×0.2 + 600×0.8) / 1,000,000 = ¥0.088`。
- DeepSeek：空闲 `¥0.44`，高峰 `¥0.88`。
- GPT-6 Luna：`$0.05`。

这只是统一假设下的算例，不是本项目实测成本、充值门槛或费用承诺。真实请求长度、失败重试、推理及账户计费会影响最终金额。预算上限和用量未知时的处理仍需单独确认。
