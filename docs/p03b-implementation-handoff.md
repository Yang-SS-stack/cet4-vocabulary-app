## 实施边界与顺序

### 第一阶段：先 UI，后模拟交互验收

布局批准后才细化该阶段执行计划并制作独立模拟预览。推荐三个同级标签“规则建议／AI 建议／依据”；AI 页紧凑时间／目标输入、生成按钮和固定结果区域，保留原弹窗关闭、背景滚动锁定与焦点恢复。

| 步骤 | 制作对象 | 完成条件 |
| --- | --- | --- |
| 1. 布局审核 | UI 规格与本卡 | 用户确认位置、标签、结果、动画及失败提示；未通过时只改提案 |
| 2. 独立模拟预览 | 当前弹窗视觉／组件、预览专用 mock 数据与状态控制 | 输入、等待、成功、取消、失败及失效可操作；始终标识演示数据；不连接本机模型路由、Qwen 或正式学习存储 |
| 3. UI 验证 | 模拟交互检查、桌面／手机实际预览 | 连点与迟到结果不会乱序；按钮有悬停与焦点反馈；错误有文字；背景页面不延展；减少动画与手机键盘可用 |
| 4. 人工验收 | 版本对应预览及验收记录 | 一次一个操作，“1”只完成当步；只验新增 UI，不重复原页面及 P-03-A 人工验收 |
| 5. 功能阶段交接 | 根据 UI 验收更新第二阶段规格 | 记录已经确认的布局和状态；单独提交功能方案，未批准不得提前接入 |

模拟数据和场景选择控件限定于独立预览入口，不写 localStorage，不读取用户正式记录，不成为生产请求失败后的伪成功回退。第一阶段不修改后端、启用参数、密钥配置、调用计数库或学习数据版本。需要维护页状态示意时同样注明“演示／尚未接入”，不改原检查逻辑。原型用于审核交互，不能声称已经验证真实模型、后端或免费余额。

## 必须覆盖的失败与证据

- 无模型配置／未启用／会话过期／来源错误／摘要不可用时无上游调用。
- 数量、时间、未知事实、错误词书、空／完成任务、超出范围与不存在的理由依据，不能成为有效草稿。
- 网络、超时、取消、连点、跨标签并发、重启、状态库异常、截断、坏响应及 usage 缺失分别标记；禁止自动重试。
- 准确免费余额从控制台读取；只凭 usage 或 `models/limits` 不能得到剩余免费 Token。`AllocationQuota.FreeTierOnly` 与普通403／429分别处理。失败报告须含额度有余量／耗尽／过期／未知及来源；余量未知不填0。
- 模拟额度耗尽，不实际消耗额度制造故障；任何真实失败后先停重试并核查控制台，告诉用户是否与额度有关。无法直接连接浏览器时由用户当前截图协助，不宣称已自动查询。
- 密钥、连接码、会话凭据、原始请求／响应、用户目标、异常全文不能进入输出、日志或复制报告。
- 草稿不会修改学习存储；原学习、复习、更正、任务冻结、设置冲突、随机选词和每轮顺序回归。
