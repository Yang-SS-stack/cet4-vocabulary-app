## 当前职责

- main 的首次六项设置使用原 `LearningSetupModal`，保存和跳过走原逻辑；启动页、首次设置、恢复数据界面不出现助手。
- 学习、复习、任务创建、冻结、进度与统计有独立流程。即使从未打开助手，也能完整使用这些功能。
- 助手是可选对话入口和调用层。默认折叠，跨页面及学习过程中可唤出。计划配置、规则推荐、微调及确认均在窗口内。
- 本次时间和目标只用于内存草稿，不覆盖每日设置。采用此计划进入草稿确认；确认应用禁用。真实修改和任务应用归 P-03-C。
- 对话统一标注模拟；没有供应商请求、自然语言理解、真实谐音生成或额度核查。演示成功、超时、额度耗尽是用户明确选择的演示，不是实际服务状态。

## 当前组件边界

| 组件/能力 | 接口与责任 |
| --- | --- |
| `FloatingLearningAssistant` | `enabled / selectedPage / onStartLearning / now`；保持会话、阶段、入口位置和请求生命周期。`enabled` 由 App 的启动、首次设置、恢复及回退状态控制。首次打开才生成模拟问候；收起暂停活动计时器并保留消息、回复游标和剩余时间，再次打开继续本地剩余文字。 |
| `FloatingAssistantWindow` | `ref / open / onClose / onClosing / launcherRect / children`；`ref.close()` 统一收起。桌面移动缩放和按真实入口位置展开/缩回，手机底部面板、50% 手势阈值、焦点与滚动。`onClosing` 开始取消请求，`onClose` 完成一次后才继续原学习入口。 |
| `AssistantConversation` | `messages / completedReply / onRequest / now / showTasks / busy / waiting / active`；对话、输入、能力提示、真实任务只读摘要、等待和逐字呈现。`onRequest(text, optional {inputRect})` 返回是否接受；发送前记录输入矩形，唯一用户气泡移动至实际位置。`completedReply` 只播报完成文本，不逐字刷屏。 |
| `assistantMockConversation` | `ASSISTANT_CAPABILITIES` 声明当前 plan/tasks/review 提示；`mockAssistantReply(request)` 返回 `text / stage / goal`。它仍是本地模拟文本适配器，不是模型或网络接口。 |
| `AssistantPlan` | `ref / now / onBack / onStart / active`；`ref.prepare(goal)` 读取当前真实摘要和保存设置，调用既有纯规则生成内存草稿，返回草稿状态；配置、微调及确认继续校验依据，不写学习记录。手动失败演示显示独立卡片并隐藏成功结果；“使用规则建议”重新读取受保护摘要并生成内存草稿，失败保留原因与原学习入口。 |
| `assistantMotion` | 统一内容动画、350ms发送气泡移动和呈现辅助；生成文字只跟随窗口自身滚动区域，不逐字滚动外部页面。缺少动画支持时内容可见，减少动态效果或收起取消移动。 |
| 原学习系统 | `onStartLearning` 仍路由到 Today 原启动调用链；任务和记录写入只由原系统负责。 |

建议提问“设置学习计划 / 今日任务 / 安排复习”先记录为用户请求，再经过同一个模拟回应适配器处理。当前等待450毫秒，从首个字素开始每25毫秒增长实际文本，气泡随内容增长；计划请求在首个字符前准备真实规则草稿，整段完成后保留900毫秒，再重新读取依据进入审核。没有完整隐藏文本撑开空泡。等待/逐字生成时禁止重复提交；完成后新提问可替代未执行的旧切页动作。上述时间仅用于 UI 演示，不代表模型延迟。

用户明确要求：每次点击助手不得重新生成已显示的内容。当前内存请求描述保存消息ID、已知本地回复、字素数组、游标、waiting/typing/read阶段和剩余时间。收起令旧回调失效并暂停；重开同一消息从游标继续，不再次调用模拟适配器，不追加重复消息，不重播已完成引导，隐藏期间不跳页。禁用/卸载中止活动动作。此处保留范围为当前应用会话，不新增持久化聊天存储。减少动态效果可从同一完成路径显示整段文本，不影响流程。

超时/免费额度耗尽卡片内明确“模拟状态 · 未接入模型”。这两种状态是手动选择的演示；不能当作真实额度、供应商故障或服务端保护证据。失败隐藏采用/确认成功区域，保留时间和目标、内存草稿、真实任务摘要与独立原学习入口；本地规则回退同样不写记录、不应用任务。

提示帮助用户表达需求，不能变成必须经过助手才能使用的学习入口。未来问候、首次询问和普通回复都应由正式对话提供者接替；真实数字、规则计算与受控动作仍由软件负责。“采用此计划”按审核参考图使用实心圆角箭头按钮，只进入草稿确认；“确认应用计划”继续禁用。助手中删除“每日计划设置”捷径，原导航设置功能保留。

正式提供者至少需要 requestId、取消信号、pending/streaming/completed/error 状态和受控动作结果。真实输出应传递增量文本和明确完成事件；界面不得根据固定延迟推断模型已完成。保留已收到文字、一次一个活动请求、旧结果不得跳页的语义；收起后的真实供应商流取消/恢复须单独定义，不把本地已知文本的断点恢复当作网络重试或自动续费请求。服务器仍需校验权限、参数、额度与调用规则，当前本地 busy 状态不能充当服务端保护。模型回复完成且软件已准备可审核草稿后才能切换；不可仅凭模型声称“已创建”就创建任务或显示成功。失败保留独立学习入口和本地规则路径。

## 后续工具扩展用例：查词与页面跳转

用户在助手询问一个四级词汇 → Agent 调用软件的真实词表查询能力 → 软件返回匹配词条及定位信息 → 受控导航跳转词表页面 → 使用现有单词卡片展示查询结果。

词条卡片展示在词表页面，**不在悬浮对话窗内展示**。这是假设用例与未来接口方向，本轮没有实现自然语言查词、定位参数或新工具。现有词表页查询和词库加载能力可作为后续复用基础；接入方须先核对实际数据接口。

以后扩展不只限于特殊计划和查词：每项能力独立声明查询、导航或修改的权限。只读查询/跳转不创建任务、修改进度；真实学习计划修改必须按阶段实现并由用户确认，模型文本不能直接获得 store 写权限。

## Qwen 对话的后续工作

1. 在保持批准界面的前提下，设计异步对话提供者与受控调用协议；保留规则计算和普通学习独立可用。
2. 分别设计对话请求、工具调用、只读导航与需确认修改；服务端验证权限和参数，不相信客户端自报角色、额度或模型自报业务结果。
3. 审核服务器保护规则：项目相关范围、反代两类限制、调用去重/并发/限频、供应商额度与失败恢复。现有保护草稿中的参数尚未因 UI 实现获批。
4. 旧 `SessionAdviceModal` 的 guarded 生成接口仍保留用于回退，见 `p03b-ui-component-handoff.md` 的历史协议；它不是当前悬浮对话自动接入点。

当前版本、自动检查、桌面/手机生产预览与逐步验收另见 `p03b-ui-verification.md` 的最新记录。尚未接模型；手机实机与真实软键盘仍需人工检查。
